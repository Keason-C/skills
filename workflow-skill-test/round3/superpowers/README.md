# 采购品类知识问答机器人(pkbot)

采购员在命令行里问一句,机器人从大家上传的文档里找答案,**答完必须给出处**;
答不上来就老实说不知道并记下来转人工;保密资料只有对应品类的品类经理看得到。

目标不是"做个聊天机器人",而是**让知识落在库里,不落在人手里**——
新人问机器人就能上手,老人走了东西留得下来。

---

## 一、你只需要理解这几个文件夹

```
demo/library/
├── public/            公开文档,谁都能问
├── registry/          品类-负责人对照表(也算公开)
├── confidential/
│   ├── 紧固件/         保密文档,只有负责紧固件的品类经理能问
│   └── 电子元器件/      同上
└── roster.csv         人员名单,由管理员维护
```

**规矩很简单:文件放进哪个文件夹,就是什么密级。** 机器人不猜、也不会自己判断
"这段是不是报价"——猜错一次就是事故。

保密文档必须放进 `confidential/<品类名>/` 这一层。直接扔在 `confidential/` 根目录下的,
算"未分类保密文档",除管理员外谁都看不到(避免出现"没人管所以谁都能看"的漏洞)。

### roster.csv 怎么填

用 Excel 填完"另存为 CSV"就行,四列:

| 工号 | 姓名 | 角色 | 负责品类 |
|------|------|------|----------|
| G0001 | 赵六 | 管理员 | |
| G0007 | 王五 | 品类经理 | 紧固件 |
| G0009 | 孙七 | 品类经理 | 电子元器件 |
| G0042 | 李四 | 采购员 | |

角色只能填 `采购员` / `品类经理` / `管理员`。负责多个品类时用分号隔开,例如 `紧固件;包装材料`。

**名单里没有的工号会被直接拒绝服务**,不会降级成"最低权限"——身份含糊比拒绝服务危险。

## 三、演示路径(照着敲一遍就懂了)

```bash
# 1. 看看机器人认为你是谁
uv run pkbot whoami --user G0042

# 2. 库里有什么、哪些文件读不了
uv run pkbot library status --user G0001

# 3. 采购员问公开问题 —— 正常回答,带出处
uv run pkbot ask "螺栓的规格要求是什么" --user G0042

# 4. 采购员问"这个品类归谁管" —— 按对照表回答
uv run pkbot ask "不锈钢紧固件归谁管" --user G0042

# 5. 采购员问保密内容 —— 明确告知涉密并指出该找谁,绝不泄露一个字
uv run pkbot ask "去年和供应商甲谈到什么报价" --user G0042

# 6. 换成紧固件的品类经理问同一个问题 —— 能看到
uv run pkbot ask "去年和供应商甲谈到什么报价" --user G0007

# 7. 换成电子元器件的品类经理问同一个问题 —— 依然看不到(按品类隔离)
uv run pkbot ask "去年和供应商甲谈到什么报价" --user G0009

# 8. 问一个库里没有的问题 —— 老实说不知道,并记入待人工清单
uv run pkbot ask "紧固件退货怎么走流程" --user G0042

# 9. 看周报:这周问了多少、几个没答上
uv run pkbot gaps report

# 10. 品类经理补答 —— 自动生成一份新文档进库,下次机器人就会答了
uv run pkbot gaps answer <上一步显示的编号> \
  --text "填写退货单,注明批次与不合格原因,经品类经理确认后走两级审批。" \
  --user G0007

# 11. 再看周报:这条已经从待办里消失
uv run pkbot gaps report
```

> 演示用的是**离线演示驱动**(不联网、答案固定),用来展示流程与权限。
> 接真实模型见下面第五节。

## 四、它凭什么"不瞎编"

不是在提示词里请模型别瞎编,而是**它编了也过不去闸门**:

1. 每次提问只把该用户有权看到、且与问题相关的文档装进上下文。
2. 要求模型输出结构化结果,必须报出"我依据的是哪几份文档"。
3. **系统核对这些引用是不是本次真的装载过的文档。对不上就整条作废**,
   不管答案写得多漂亮,一律变成"答不上来,已转人工"。

另外三条硬规矩:

- 模型返回的格式不合法 → 作废,绝不把原始文本当答案吐出来。
- 答案没有出处 → 作废。
- 作废原因**不会回显模型报出的文档路径**——那可能正是一份该用户无权看到的保密文档,
  回显等于隔着闸门把文件名漏出去。

## 大文件怎么办

需求方原话是"读不动宁可说读不动",所以:

- 装得下就整篇读;
- 装不下就只读命中问题的那几章,并在答案末尾写一句
  "《XX》太大,我只读了与问题相关的部分章节";
- 实在读不动就跳过,并明说"《XX》太大,这次没能读进来"。

打不开的格式(.wps、加密 PDF、扫描件……)不装懂、不猜内容,
统一在 `pkbot library status` 里列出来,让管理员知道有哪些知识实际上没进库。

## 五、接真实模型

```bash
uv sync --extra llm
export ANTHROPIC_API_KEY=...
uv run pkbot ask "螺栓的规格要求是什么" --user G0042 --driver anthropic
```

用的模型是 `claude-opus-5`。真实调用集中在 `src/pkbot/anthropic_driver.py` 一个文件里,
其余所有逻辑(权限、检索、引用校验)都不依赖它,所以测试可以完全离线跑。

---

## 六、为什么不用向量库

需求方明确否决,而且几十份文档上做 embedding 属于杀鸡用牛刀,还多一个需要维护的索引状态。
这里用的是**确定性检索**:关键词打分(词频 + 逆文档频率,中文按二元组切)排序,
在 token 预算内装载。好处是**"读哪份文档"这个决定可以被完整单测**——
而"答得准"这件事的底座恰恰在这里。模型只负责读给定材料、组织语言、报出引用。

## 七、以后接企业微信

对话入口(`src/pkbot/cli.py`)与问答内核(其余模块)是分开的,
`ask()` 就是内核的入口。接企业微信只需要再写一层壳去调它,内核不用改。

## 八、代码结构

| 文件 | 职责 |
|------|------|
| `models.py` | 数据结构 |
| `identity.py` | 名单 → 身份;未知工号拒绝服务 |
| `ingest.py` | 各种格式 → 带出处的文本小节;读不了就明说 |
| `library.py` | 扫目录;密级/品类由路径决定 |
| `access.py` | 权限闸门(纯函数,前置于一切检索) |
| `retrieval.py` | 关键词打分 + 上下文预算装载(纯函数) |
| `drivers.py` | LLM 接口 + 离线实现 |
| `anthropic_driver.py` | 真实调用(测试从不触碰) |
| `answering.py` | 组 prompt、解析、**引用校验闸门** |
| `gaps.py` | 未答清单、周报、补答回填 |
| `cli.py` | 命令行组装 |

设计文档在 `docs/superpowers/specs/`,实施计划在 `docs/superpowers/plans/`。
