## Strengths

- **权限闸门位置正确**(`access.py:36-42`)。`partition` 前置于一切检索,
  不可见文档从不进入打分、也从不进入上下文——模型物理上不可能引用到它们。
  这比"在提示词里叮嘱模型别看保密内容"强一个数量级。
- **引用校验闸门是确定性的**(`answering.py:97-108`)。答案必须报出 doc_id,
  且必须落在本次真实装载的集合里,否则整条作废。这条闸门可以在没有真模型的情况下被完整测试
  (`test_answering.py:36-49`),这一点很关键:靠模型自觉的保障在离线测试里等于没有保障。
- **不回显模型报出的 doc_id**(`answering.py:102-106`)带注释说明了原因。
  这是个容易被当成"友好错误提示"写反的地方。
- **"没读全"如实告知**(`answering.py:56-67`)贯穿到 CLI 输出,
  与需求方"读不动宁可说读不动"的要求对得上。
- **测试用真实二进制 fixture**(`conftest.py`)而不是字符串假装解析,
  .docx/.xlsx/.pdf 都是当场生成的真文件。
- `test_drivers.py:33-35` 用 `assert "anthropic" not in sys.modules` 把
  "真实调用只写不跑"变成了一条可执行的断言,而不是一句口头承诺。

## Issues

### Critical(必须修)

**C1. `resolve_gap` 存在路径穿越,可在文档库之外任意写文件**

- 位置:`src/pkbot/gaps.py:112-116`
- 问题:`category` 直接来自 CLI 的 `--category`,未经校验就拼进路径:
  `library_root / "confidential" / category / "faq"`。
- 探针验证:`--category "../../../tmp/reviewprobe/ESCAPED"` →
  实际写入 `/tmp/tmp/reviewprobe/ESCAPED/faq/xxx.md`,**在库外**。
- 为什么要紧:一个已认证用户可以把文件写到文件系统任意位置。
- 修法:校验 `category` 不含路径分隔符与 `..`,并在拼接后断言最终路径仍在
  `library_root` 之内。

**C2. `resolve_gap` 没有任何授权检查,采购员可以往保密目录里塞文档**

- 位置:`src/pkbot/gaps.py:100-140`、`src/pkbot/cli.py:_cmd_gaps_answer`
- 问题:`author` 参数只被用来署名,从未被用来判断"你有没有资格补答"。
- 探针验证:以 `ROLE_BUYER` 身份调用,成功写入
  `library/confidential/紧固件/faq/xxx.md`。
- 为什么要紧:整个项目的核心卖点是权限隔离。一个采购员既不能**读**保密文档,
  却能**写**进保密目录——他可以把任意内容注入知识库,而那些内容随后会被
  品类经理当作可信资料读到并引用。这是权限模型上的一个反向缺口,
  比读泄露更隐蔽。
- 修法:补答限定为 `品类经理` 或 `管理员`;标为保密时,品类经理只能写自己负责的品类
  (与读权限对称);管理员不受限。

### Important(应该修)

**I1. `__pycache__/*.pyc` 被提交进仓库**

- 位置:`src/pkbot/__pycache__/`、`tests/__pycache__/`
- 原因:`.gitignore` 是在最后一次提交才加的,此前已被 `git add -A` 纳入索引。
- 修法:`git rm -r --cached` 后重新提交。

### Minor(可以later)

**M1. 每次提问都全量重扫并重解析文档库**(`cli.py:ask`)。
几十份文档规模下没问题,但需求方提到了上百页招标文件和几千行 Excel,
每次 `ask` 都要重新解析一遍。建议后续加一层按 mtime 的解析缓存。
现在不做符合 YAGNI,但应记录在案。

**M2. `gaps report` 不需要身份**(`cli.py:build_parser`)。任何人都能看到待办清单里的
问题原文,其中可能包含"去年和某供应商谈到多少钱"这类本身带信息的提问。
建议后续给 report 也加 `--user` 并限定品类经理/管理员可见。

**M3. 名单里工号重复时静默覆盖**(`identity.py:load_roster`)。
建议报错而不是取最后一条,避免管理员改错了却看不出来。

**M4. 同一个 gap 可以被重复补答**,后一次覆盖前一次生成的文档。
不算 bug,但没有提示。

## Recommendations

- C1 和 C2 是同一处代码的两个方向(路径、身份),建议一并修,并各配一条回归测试。
- 建议把"写入库"这件事也看成一个需要过闸门的动作,而不只是"读"需要。
  当前设计里 `access.py` 只管读,写路径完全没有对应的守卫,这是概念上的不对称。

## Assessment

**Ready to merge?** With fixes(C1、C2 必须先修,I1 顺手修)

保密区注入内容——这恰好绕过了项目的核心卖点,必须在合并前修掉。
