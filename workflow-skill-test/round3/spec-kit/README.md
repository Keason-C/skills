# 采购 Commodity Know-How 问答机器人

给采购部用的命令行问答机器人:读大家上传到共享盘的 Word / PDF / Excel / Markdown,
回答"这个品类归谁管、供应商有哪些、规格要求是什么、走什么流程"这类问题。

三条设计底线:

1. **不瞎编。** 每句话都要有出处;答不上来就老实说不知道,并当场告诉你该找谁。
2. **保密的看不到。** 报价、成本、谈判策略只有**负责该品类的**品类经理和采购负责人能看。
   这不是靠"叮嘱机器人别说",而是那些内容**根本没被读进来**。
3. **知识落在库里,不落在人手里。** 答不上来的问题会自动攒成一份"知识缺口清单",
   告诉部门最该补哪些文档。

## 5 分钟上手

```bash
uv venv && uv pip install -e ".[dev]"

# 造一套假的演示语料(公司名、人名、价格全是编的)
uv run python scripts/build_demo_corpus.py

# 建索引
uv run pbot ingest --corpus demo/corpus --roster demo/roster.csv --state .pbot

# 提问(P1001 = 普通采购员)
uv run pbot ask "电解铜这个品类归谁管" --user P1001 \
  --corpus demo/corpus --roster demo/roster.csv --state .pbot
```

想一次看完全部 13 个验收场景(含保密、冲突、多格式):

```bash
uv run python scripts/demo_walkthrough.py
```

**全程不需要联网,也不需要 API key** —— 演示与测试都跑在一个确定性的本地 mock 上。

## 它长什么样

**有据可答:**

```
【答案】
本品类负责人:张伟(工号 P1002),分机 8021。

【出处】
  [1] 品类管理手册-电解铜.md — § 电解铜品类管理手册 / 品类归属
      "本品类负责人:张伟(工号 P1002),分机 8021。……"
```

**答不上来 —— 老实说,并告诉你找谁:**

```
【答案】
资料里没有查到相关内容,我不能凭猜测回答。(「钛」在现有资料中从未出现过)

→ 已转人工:请联系 王芳(工号 P1003)
   本次提问已记入清单(编号 a0ba3f40b163)。
```

**权限不够 —— 一个字都不透:**

```
【答案】
该问题涉及受限信息,你当前的权限无法查看。

→ 请联系 张伟(工号 P1002)、赵强(工号 P1005)
```

**两份文件说法不一样 —— 都摆出来,不替你做决定:**

```
【答案】
资料中有多处相关说明,内容不一致,请自行核实后再执行。以下为全部来源,系统不做裁决。

【出处】
  [1] 规格要求-紧固件-补充.md — § 表面处理   "……一律采用镀锌钝化,盐雾试验不低于 480 小时。"
  [2] 规格要求-紧固件.md     — § 表面处理   "……采用达克罗(Dacromet),盐雾试验不低于 720 小时。"

⚠ 资料不一致,请自行核实:两份文件均未标注生效日期或版本号,系统不做裁决。
```

**有新旧版本 —— 按新的答,但告诉你还有旧的:**

```
ℹ 另有旧版:《采购流程说明-2019旧版.docx》(生效日期 2019-05-01),本次未采用。
```

## 共享盘怎么摆

完整版见 [contracts/corpus-layout.md](specs/001-procurement-knowhow-bot/contracts/corpus-layout.md)
(那一份是写给采购部同事看的,不含技术术语)。三条规矩:

```
采购知识库/
├── roster.csv              ← 人员名单
├── 品类管理手册-电解铜.md    ← 普通文件,随便怎么放
└── 保密/                   ← ★ 放进来的整份文件都算保密
    ├── 电解铜/             ← ★ 必须按品类再分一层
    │   └── 2025年度报价表.xlsx
    └── 集团年度成本目标.md   ← 没归品类的,只有采购负责人能看
```

1. 保密的东西放进"保密"文件夹,**整份**算保密。
2. "保密"文件夹里按品类分子文件夹,文件夹名要和名单里的"负责品类"一致。
3. 系统**不会**自己猜哪份文件保密。不放进去就是公开的。

人员名单模板:

```bash
uv run pbot roster-template > roster.csv   # UTF-8 with BOM,Excel 打开不乱码
```

| 工号 | 姓名 | 角色 | 负责品类 |
|------|------|------|----------|
| P1001 | 李明 | 采购员 | (留空) |
| P1002 | 张伟 | 品类经理 | 电解铜 |
| P1005 | 赵强 | 品类经理 | 电解铜;铝锭 |
| P9000 | 陈国华 | 采购负责人 | `*` |

加了新文件之后,跑一次 `pbot ingest` 就行,**不用找 IT**。

## 六条命令

| 命令 | 干什么 |
|------|--------|
| `pbot ingest` | 扫描语料建索引,并列出读不了的文件 |
| `pbot ask "问题" --user 工号` | 提问 |
| `pbot gaps` | 知识缺口清单(按被问次数排序),品类经理每周看一次 |
| `pbot rejected` | 哪些文件没能进知识库,以及为什么 |
| `pbot audit` | 审计日志(谁问了什么、命中了什么、是否转人工) |
| `pbot roster-template` | 打印人员名单模板 |

"不知道"和"权限不足"都是**正常业务结果**,退出码是 0,不是错误。

## 能力边界(请务必读完这一节)

这个系统被刻意做成"宁可漏答,不可错答"。下面是它**做不到**的事,写在这里是为了
不让任何人对它产生错误期待。

1. **不用向量库,所以问法和文档用词差太多时会漏。**
   问"铜",而文档里写的是"电解铜 Cu-CATH-1",可能匹配不上。
   这时它会说"没查到"并转人工 —— 是漏答,不是错答。
   (这是需求方明确要求的:"不要搞 RAG 那种向量库的方案,太重了"。)

2. **能拦住"编造出处",拦不住"曲解出处"。**
   系统会验证模型引用的每一段材料是否真的存在,引用文字由代码从原文截取、模型无法伪造。
   但如果模型引用了一段真材料却理解错了意思,系统**发现不了**。
   缓解办法是每条答案下面都并排展示原文摘录 —— **请养成扫一眼出处的习惯。**

3. **只能发现"同一主题的多个版本",不能发现任意语义矛盾。**
   《采购流程说明》和《采购流程说明-2019旧版》会被识别为冲突;
   但两份标题完全不同、内容却互相打架的文件,系统看不出来。

4. **"从未出现过的词"这条防线是个启发式,而且只对中文生效。**
   中文问题里如果出现了资料中彻底没有的实词(比如库里只有普通紧固件的资料,
   你问"钛合金紧固件"),会直接判为不知道 —— 这是防"答非所问"的主力。
   它靠一份**虚词/常用动词表**把"的、是、走、查"这类词排除在外;
   这份表不可能完美,偶尔会把某个生僻但正常的词当成"未知实词"从而多答一次
   "不知道"。**方向是安全的(宁可漏答),但确实会有误伤。**
   表在 `src/procurement_bot/retrieval.py` 的 `_STOPCHARS`,可以直接加字。
   英文提问不走这条防线,只依赖检索得分。

5. **不做扫描件 OCR。** 图片型 PDF 会进"未纳入知识库"清单,不会被静默跳过。

6. **不判断文档是否过期。** 它只忠实呈现文档里写的日期。哪份更权威,是人的判断。

7. **响应时间**:本地检索是毫秒级;接真实模型后的总耗时取决于模型服务,
   **不在离线验收范围内**。

## 接真实模型

```bash
uv pip install -e ".[anthropic]"
export ANTHROPIC_API_KEY=...
uv run pbot ask "电解铜归谁管" --user P1001 --driver anthropic
```

真实驱动在 `src/procurement_bot/llm/anthropic_driver.py`,**只写不跑**:
它不参与任何自动化测试(测试全部离线)。换别家模型只需要再写一个实现了
`LLMDriver` 协议的类,业务逻辑一行都不用改。

## 开发

```bash
uv run pytest                        # 142 个测试,全部离线,0.8 秒
uv run python scripts/demo_walkthrough.py   # 13 个验收场景
```

测试里有一个 autouse fixture 会**切断所有网络连接**:任何测试一旦尝试联网就立刻失败。
可以拔掉网线验证。

`tests/test_constitution.py` 把项目宪法变成了会失败的断言 —— 引入向量库、
在核心里 import 厂商 SDK、把品类名硬编码进代码,都会让它变红。

### 代码结构

```
src/procurement_bot/
├── core.py         ← 唯一的问答入口 AskService.ask(渠道无关)
├── cli.py          ← 薄适配器,以后接企业微信不用动 core
├── authz.py        ← 权限过滤(在组 prompt 之前)
├── retrieval.py    ← 中文 bigram + IDF 打分,确定性、可解释
├── verifier.py     ← 防幻觉:验证引用真实存在
├── conflict.py     ← 同主题多版本的裁决
├── escalation.py   ← 转人工与知识缺口
├── ingest/         ← 五种格式的解析与导入
└── llm/            ← 驱动接口 + 离线 mock + 真实驱动
```

完整的规格、设计与决策记录在
[`specs/001-procurement-knowhow-bot/`](specs/001-procurement-knowhow-bot/):
spec(需求)、research(12 条技术决策及被否决的方案)、data-model、contracts、tasks。
