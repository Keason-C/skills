# Spec — 采购品类知识问答(commodity-qa-bot)

**Status:** ready-for-agent

术语一律按 `CONTEXT.md`。相关决策:ADR-0001(不用向量库)、ADR-0002(权限在模型之前)、ADR-0003(不可核验即弃答)、ADR-0004(LLM 在驱动之后)、ADR-0005(保密文件夹是唯一判据)。

## Problem Statement

采购部这么多年的品类知识,长在老采购的脑子里。人一走,交接就断:新来的采购员不知道这个品类归谁管、有哪些合格供应商、上次是怎么谈下来的、规格卡在哪几条、要走什么流程,只能一个个去问人。同时这些知识**并不是完全没写下来** —— 同事陆陆续续交过一堆文档,Word、PDF、Excel、Markdown 都有,散在文件夹里,格式五花八门,但没人翻得动、也不知道该翻哪一份。

于是出现两个问题叠在一起:**知识找不到**(有文档也等于没有),以及**知识留不住**(人走了就断)。领导要的不是一个聊天玩具,是让知识落在库里、不落在人手里。

另有一条硬约束:供应商报价、成本、谈判策略这类内容,普通采购员不能看到,只有对应品类的品类经理能看。这不是个附加功能,它是这套东西能不能上线的前提。

## Solution

一个命令行问答机器人。把知识文档所在的文件夹交给它,它读一遍、建好**知识目录**,之后采购员用自己的工号提问,它给出带**出处**的中文回答。

四条决定这东西"靠谱"的性质:

1. **答案必须有出处**,而且出处会被系统逐字核对回原文;核对不过就不给答案。
2. **答不上来就明说不知道**,并**转人工**到对应品类的品类经理 —— 弃答是正确结果,不是故障。
3. **保密内容对没权限的人根本不会被送进模型**(不是"让模型别说"),但会明确告诉提问人"这个问题涉及保密,已转给谁",而不是假装库里没有。
4. **每一次答不上来都被记成一条知识缺口**,按品类攒成清单 —— 这是交付给领导的第二产物:它自动指出库里还缺哪块知识、该找谁补,老采购走之前照着这张单子交接。

先做命令行,以后接企业微信 —— 所以核心是一个不知道命令行存在的模块,命令行只是它的第一个前端。

## User Stories

1. 作为**采购负责人**,我想把一个文件夹指给机器人让它读进去,这样我不用改变同事现有的交文档习惯。
2. 作为**采购负责人**,我想在摄取之后拿到一份**摄取报告**,说清楚哪些读进去了、哪些没读进去、各自为什么,这样我知道库里到底有什么,不会被静默丢掉的文件坑到。
3. 作为**采购负责人**,我想知道哪些文件是扫描件(拍照/扫描出来、文字是图片),这样我心里有数缺了哪一块,以后再决定要不要单独做文字识别。
4. 作为**采购负责人**,我想自己维护一张**人员名单**(工号/姓名/角色/负责品类),用 Excel 或 CSV 都能填,这样不需要 IT 介入就能加人改人。
5. 作为**采购负责人**,我想指定一个**兜底接收人**(我本人),这样没人认领的品类的问题不会掉在地上。
6. 作为**采购员**,我想用自己的工号提问,这样系统知道我是谁、我能看什么。
7. 作为**采购员**,我想问"这个品类归谁管",得到品类经理的名字,这样我知道该找谁。
8. 作为**采购员**,我想问"有哪些合格供应商",得到供应商名单,这样我不用去翻文件夹。
9. 作为**采购员**,我想问"规格要求是什么",得到规格条目,这样我能直接用。
10. 作为**采购员**,我想问"走什么流程",得到流程步骤,这样我不用一个个问老同事。
11. 作为**采购员**,我想每条回答都带**出处**(哪份文档、哪一段),这样我能自己去核实,而不是盲信机器人。
12. 作为**采购员**,当机器人不知道时,我想让它直接说"不知道",而不是编一个听起来很像的答案,这样我不会拿着编造的条款去跟供应商谈。
13. 作为**采购员**,当机器人答不上来时,我想立刻知道该找谁(姓名+联系方式),这样我不会卡在这儿。
14. 作为**采购员**,当我问到保密内容时,我想被明确告知"这个问题涉及保密、你的权限看不到、已转给张三",而不是被告知"库里没有",这样我不会误以为公司没有这份知识。
15. 作为**采购员**,我不想看到任何保密内容,哪怕是片段、摘要或标题的正文引用。
16. 作为**品类经理**,我想问出自己负责品类的报价、成本和谈判策略,这样我干活不用绕开这个系统。
17. 作为**品类经理**,我不应该能问出**别的**品类的保密内容,这样权限边界是按品类切的,不是按职级切的。
18. 作为**采购员**,当两份文档说法不一致时,我想看到两个说法**并排列出并标注各自日期**,而不是机器人替我裁决,这样我自己判断哪份现行。
19. 作为**采购员**,我想让写了生效日期的文档优先于没写日期的旧文档,这样我拿到的默认是较新的说法。
20. 作为**采购负责人**,我想拿到一张按品类分组的**知识缺口**清单,这样我知道该催谁补什么文档。
21. 作为**采购负责人**,我想让每一次转人工都留下问题、提问人和时间,这样问题有主、可追。
22. 作为**采购负责人**,我想有一份只留在本地的访问记录,尤其是谁看了保密内容,这样出事能查、平时没人看。
23. 作为**采购负责人**,我想让机器人回答慢一点没关系(5~15 秒可接受),但不能贵得离谱,这样它能长期开着。
24. 作为**工程师**,我想让全部测试离线跑,这样 CI 不依赖模型服务、也不烧钱。
25. 作为**工程师**,我想让核心问答模块不知道命令行的存在,这样以后接企业微信时不用重写它。
26. 作为**新来的采购员**,我想在没人带的情况下靠问机器人上手,这样我的第一周不用占用别人半天。

## Implementation Decisions

### 模块与接口(用 `/codebase-design` 的词)

- **`llm` — 驱动seam。** 接口只有一个方法:输入 prompt 字符串,输出文本。两个 adapter:真实的 Anthropic 驱动(写但测试永不跑)和脚本化假驱动(测试全用)。两个 adapter 意味着这是个真 seam,不是假想的。见 ADR-0004。
- **`ingest` — 摄取模块。** 接口:给一个知识库根目录和一个驱动,返回一个**知识库**(知识目录 + 摄取报告)。深:内部处理格式分派、文本抽取、扫描件识别、品类推断、保密判定、生效日期抽取、摘要生成,全部藏在接口后面。
- **`people` — 人员名单模块。** 接口:给一张表的路径,返回名单;按工号查出**提问人**。CSV 与 XLSX 同一个接口。
- **`access` — 权限模块。** 纯函数:给知识目录和提问人,返回一个可见性划分(可见的 / 被挡下的)。**这是系统唯一的安全边界**,被挡下的文档正文与摘要绝不进入任何发给模型的字符串。见 ADR-0002。
- **`answering` — 问答模块。** 接口:`answer_question(问题, 提问人, 知识库, 驱动) -> 回答`。深:内部包含两段式选材(先目录后正文)、结构化输出解析、出处逐字核验、弃答降级、保密提示、转人工构造。不打印任何东西、不读 argv、不知道 CLI 存在。
- **`records` — 记录模块。** 知识缺口、访问记录、转人工记录,追加写本地文件。
- **`cli` — 前端。** 薄:`ingest` / `ask` / `gaps` / `audit` / `whoami` / `doctor`。只做参数解析和渲染。
- **`rehearsal` — 离线排练驱动(补记)。** 一个不联网、不调模型的确定性 `LlmDriver`,让演示路径在没有 API key 的情况下也能完整跑通。**它不是模型,也不冒充模型。**这一条是实现期为满足「测试与演示不得联网」这条环境红线补进来的,见 code-review 的 Spec #4。
- **`config` — 知识库落盘(补记)。** `ingest` 把知识目录连正文存成一份 JSON,`ask` 直接加载,免得每问一次就重新摄取、重新生成摘要。

### 关键行为

- **两段式选材(ADR-0001)**:第一次调驱动 = 拿知识目录选文档(默认最多 4 份);第二次调驱动 = 拿选中文档全文作答。
- **保密判定(ADR-0005)**:只看文档是否位于保密文件夹之下,没有第二判据。品类由保密文件夹下一级目录名或文档所在目录名推断。
- **品类经理可见范围**:只可见自己负责品类的保密文档。
- **出处核验(ADR-0003)**:模型返回 `{"answered": bool, "answer": str, "citations": [{"document_id": str, "quote": str}], "reason": str}`。每条 citation 的 `document_id` 必须属于本次真正喂进去的文档集合,`quote` 规范化空白后必须逐字出现在该文档正文里。任一条不过 → 整条回答作废 → 弃答。
- **收敛到弃答**:驱动异常、JSON 不合法、字段缺失、`answered=false`、citations 为空、核验失败、没有可见文档 —— 全部产出弃答 + 转人工。
- **保密提示(ADR-0002 次生)**:在进程内对被挡下文档做**不经过模型**的相关性判断 —— 问题与"标题+品类"的字符二元组重合度达阈值,或问题命中保密话题词且重合度非零。命中则在回答里附一句"该问题涉及保密内容,你的权限看不到,已转给 X",并转人工。回答与提示可以同时出现(部分能答、部分涉密)。
- **时效与冲突**(⚠️ 部分**本质上不可验证**:排序、prompt 带日期、prompt 指令三样都有测试,但「模型是否真的并排列出」取决于模型本身,而测试离线 —— 这条应视为 **prompt 级尽力而为**,不是已验收能力。见 code-review 的 Spec #1):摄取时从正文抽取生效日期(支持 `2024-01-01`、`2024年1月1日`、`2024/01/01` 等写法);喂给模型的文档按生效日期倒序、无日期者按摄取时间兜底;prompt 明确要求"说法不一致时并排列出并标注日期,不要替用户裁决"。
- **转人工目标**:该品类的品类经理;无人认领则兜底接收人。
- **格式支持**:`.docx` `.pdf` `.xlsx`/`.xlsm` `.md` `.txt`。其它一律列入摄取报告的"未读入"并注明原因。PDF 抽不出文字层 → 标记为疑似扫描件,单独成组。

## Testing Decisions

**什么是好测试**:只测**外部行为**,不测内部构造。测试通过公开接口观察,不 mock 自己写的协作者,不断言调用次数,期望值来自独立的已知字面量而不是把实现算法重算一遍。测试名读起来应该像一句规格("采购员问到报价时拿不到保密文档的任何文字")。

**seam(已确认,只测这三个)**:

1. **`ingest` 的接口** — 真实的临时目录 + 真实的 `.docx`/`.xlsx`/`.pdf` 文件(测试时由夹具现场生成,不入库二进制),观察知识目录与摄取报告。文件系统在这里不 mock —— 它是被测行为本身。
2. **`answer_question` 的接口** — 主战场。绝大多数行为测试在这里,驱动用脚本化假驱动注入。权限、核验、弃答、保密提示、转人工、冲突呈现都在这个 seam 上测。
3. **`cli.main(argv)` 的接口** — 少量端到端冒烟测试,证明"命令行里真的能用"。

**唯一被 mock 的东西是 `LlmDriver`** —— 它是系统边界(外部 API),符合 `/tdd` 的 mocking 规则。其余一律用真东西。

**安全边界的测法**:不测"模型没说出保密内容"(那是在测模型),而是直接断言**发给驱动的 prompt 字符串里不含保密文档的正文串**。假驱动会捕获收到的全部 prompt,测试对它做子串断言。这是 ADR-0002 唯一可信的验证方式。

**prior art**:无,绿地项目。本 spec 定义的三条 seam 即是后续的 prior art。

## Out of Scope

- 扫描件文字识别(OCR)。第一版只**报出来**哪些是扫描件。业主估计只占一两成,接受。
- 企业微信接入。只保证核心模块不被 CLI 污染,不写任何企业微信代码。
- 段落级保密、每份文档的元数据卡片 —— 业主明确否决(ADR-0005)。
- 向量库 / embedding / 任何检索索引基础设施(ADR-0001)。
- 文档写入或修改。系统只读知识文档。
- 多轮对话与上下文记忆。第一版一问一答。
- 权限的真实身份认证。命令行阶段凭工号自报,以人员名单为准;企业微信阶段再谈真实认证。
- 并发、服务化、数据库。全部是本地文件。

## Further Notes

- 现在**一份真实文档都没有**,业主也暂时拿不出脱敏样例。因此演示语料是我们合成的假采购文档(品类策略、供应商名录、规格书、报价单、谈判纪要,中英混排),这一点必须在 README 里写清楚,免得日后有人误以为是真数据。
- 真实文档的排版千奇百怪,第一次拿到真语料时,预期要在**文本抽取**和**品类推断**两处返工。摄取报告的存在就是为了让这次返工是可见的、可量化的。
- 知识缺口清单的价值随时间增长:它是这个项目对领导"知识不落在人手里"这个目标的直接回应,建议每月和品类经理过一次。
