# 回答必须可机械核验,核验不过一律降级为弃答

业主的核心诉求是"别瞎编乱答,答不上来老实说不知道"。在提示词里写"不要编造"是无效的 —— 它无法被测试,也无法被信任。

我们把它实现为一道**机械闸门**:模型必须返回结构化结果,每条论断都附**出处**(文档 id + 逐字原文片段);系统随后校验每条出处的文档 id 确实在本次喂给模型的集合里,且引用片段规范化空白后确实**逐字出现**在该文档正文中。任何一条校验不过,整个回答被丢弃,降级为**弃答** + 转人工。

因此"答不上来老实说不知道"不是一句嘱咐,而是**默认路径**:模型输出不合法、引用对不上、驱动报错、超时 —— 一切异常都收敛到弃答。

## Consequences

宁可不答不可错答,意味着**召回率被主动牺牲**:模型明明知道、但引文抄错一个字的回答也会被毙掉。这是刻意的取舍 —— 一个偶尔说"我不知道"的机器人还能用,一个偶尔编造供应商条款的机器人会毁掉整个项目的信任,而信任是"知识落在库里"这个目标的前提。

副产品:每一次弃答都是一条**知识缺口**记录,这正是业主要的第二产物。
