# 保密文件夹是唯一的定密判据

设计时我们提过两个更细的方案:每份文档旁边放一个同名元数据小卡片,以及在正文里用 `[保密]` 行标记段落级保密。采购负责人**两个都否决了**,理由是运营现实而非技术:"说实话大家不会用,坚持不了两周","别搞同名卡片文件,没人会维护"。

于是判据只剩一条:**文档在不在保密文件夹里**。不在保密文件夹 = 公开。混写了公开内容的文档整份从严;采购员要问其中公开的那部分,走转人工。规矩是"保密的必须放保密文件夹",放错由上传人负责,这一条业主表示内部管得住。

## Consequences

后来者看到这套设计,几乎一定会想"加个 per-document metadata 不就更灵活了吗"——**这正是被明确拒绝的东西**,拒绝理由是没人会维护它,而一个没人维护的定密机制比没有更危险(它会让人以为标过了)。要重开这个决定,先证明有人真的会长期维护它。

代价是已知且被接受的:一份既有规格又有报价的文档,采购员连规格也问不到。业主认为这个代价可以接受,并靠转人工兜住。
