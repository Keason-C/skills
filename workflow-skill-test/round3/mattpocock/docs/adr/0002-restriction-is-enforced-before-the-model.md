# 权限过滤发生在模型之前,而不是靠提示词约束模型

保密知识的边界是这个系统唯一的安全边界。最省事的实现是把全部文档喂给模型,然后在系统提示词里写"如果提问人不是品类经理,不要透露报价和成本" —— 我们**明确拒绝**这条路。那等于先把保密内容送到模型面前,再祈祷它守口如瓶;一次提示词注入、一次越狱、一次模型抽风就是一次泄露,而且泄露了你还不知道。

因此:按提问人的角色和负责品类裁剪语料这一步,发生在**构造请求之前**。采购员发起的那次请求里,保密文档的正文、摘要、乃至标题都不存在于 prompt 字符串中。这条边界由直接断言 prompt 文本的测试钉死,而不是由断言"模型没说出来"的测试钉死。

## Consequences

由此产生一个次生问题:保密文档既然对模型不可见,系统怎么知道该告诉采购员"这个问题涉及保密"?答案是**在进程内、不经过模型**地做一次相关性判断 —— 拿问题和被挡下文档的标题+品类做字符二元组重合度计算。这是刻意的:被挡下文档的信息只在本进程内参与一次布尔判断,永远不进入任何发给模型的字符串。

采购负责人已确认取"明说但不透露"策略:告诉提问人"该问题涉及保密内容,已转给 X",而不是假装库里没有 —— 假装没有会误导人,也会污染知识缺口统计。
