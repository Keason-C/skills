# 采购品类知识问答(commodity-qa-bot)

采购部的品类知识问答机器人,先做命令行,以后接企业微信。

把同事平时交上来的文档(Word / PDF / Excel / Markdown / txt)所在的文件夹交给它,
它读一遍建好目录,之后采购员用自己的工号提问,拿到**带出处**的中文回答。

四条决定它靠不靠谱的性质:

1. **答案必须有出处**,而且出处会被系统**逐字核对回原文**;核不上就不给答案。
2. **答不上来就明说不知道**,并**转人工**给对应品类的品类经理 —— 弃答是正确结果,不是故障。
3. **保密内容对没权限的人根本不会被送进模型**(不是"叮嘱模型别说"),但会明确告诉提问人
   "这个问题涉及保密、已转给谁",而不是假装库里没有。
4. **每一次答不上来都记成一条知识缺口**,按品类攒成清单 —— 这是交给领导的第二产物:
   它自动指出库里还缺哪块知识、该找谁补。

> ⚠️ **`demo/knowledge/` 里的全部内容都是合成的假数据。**
> 假供应商、假价格、假条款,一个字都不是真的 —— 真实文档一份都还没拿到。
> 别把里面的"报价"当真,更别拿去跟谁谈判。生成脚本见 `scripts/make_demo_corpus.py`。

## 装

需要 Python 3.11+ 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync                 # 装运行与测试依赖
uv sync --extra llm     # 想接真模型时再装 anthropic SDK
```

## 跑测试

```bash
uv run pytest
```

**全部测试离线可跑**,不需要 API key,不碰网络。真实的模型调用写在
`llm.AnthropicDriver` 里,但**测试永远不执行它**(见 `docs/adr/0004-*.md`)。

## 演示路径(全程离线,照着抄就行)

演示用 `--driver rehearsal` ——「排练驱动」是一个**不联网、不调模型**的确定性替身
(`src/procurement_qa/rehearsal.py`)。它靠字符匹配挑文档、靠逐字抄原文造回答,
**回答质量当然远不如真模型**,但整条流水线的行为 —— 尤其是权限边界、出处核验、
弃答、转人工、记录 —— 和接真模型时**完全一样**。

```bash
# 0. 生成演示语料(已经在仓库里,想重来一次再跑)
uv run python scripts/make_demo_corpus.py
```

### 1)摄取:读一遍知识库,顺便说清楚哪些没读进来

```bash
uv run pqa ingest --driver rehearsal
```

```
读入 11 份,未读入 2 份。
其中保密文档 3 份(位于「保密」文件夹下)。

没读进来的文件:
  - 合同/2022框架协议扫描件.pdf
      原因:PDF 里没有文字层,疑似扫描件(本版不做文字识别)
  - 杂项/旧系统导出.dat
      原因:不支持的文件格式(.dat)
```

没读进来的文件**逐个列名**。"大家交上来什么算什么"的现实里,静默丢文件等于知识黑洞。

### 2)采购员问一个公开问题

```bash
uv run pqa ask --as 1001 --driver rehearsal "金属品类的付款账期是多久?"
```

```
根据库里的文档:三、付款条件
标准账期为月结 60 天(NET 60),新供应商首年为月结 30 天。

出处:
  - 金属品类策略2024(金属/金属品类策略2024.docx)
      原文:三、付款条件
标准账期为月结 60 天(NET 60),新供应商首年为月结 30 天。
```

演示语料里**故意放了一份 2021 年的旧版策略**(写的是月结 30 天)。喂给模型的文档
按生效日期倒序排列,并且 prompt 明确要求"说法不一致时并排列出并标注日期,不要替用户裁决"。

### 3)同一个采购员问报价 —— 被明确挡下

```bash
uv run pqa ask --as 1001 --driver rehearsal "金属供应商的报价单价是多少?"
```

```
[权限] 该问题涉及保密内容(供应商报价、成本、谈判策略),你的权限看不到。已转给 王敏(wangmin@example.com)。

[转人工] 已记录,请联系 王敏 wangmin@example.com
```

报价单里的数字一个都没露。**它压根没进过发给模型的字符串** —— 过滤发生在模型之前。

### 4)品类经理问同一个问题 —— 拿得到

```bash
uv run pqa ask --as 2001 --driver rehearsal "金属供应商的报价单价是多少?"
```

```
根据库里的文档:供应商 | 料号 | 单价(元/吨) | 年度折扣 | 阶梯价起订量(吨)
华兴金属制造 | MTL-1001 | 4820 | 3.0% | 50
```

### 5)越权:金属品类经理问包材的底价 —— 照样挡

```bash
uv run pqa ask --as 2001 --driver rehearsal "包材的谈判底价是多少?"
```

权限边界是**按品类切的,不是按职级切的**:管金属的查不了包材的底价,转给赵磊。

### 6)答不上来:老实说不知道,并转人工

```bash
uv run pqa ask --as 1001 --driver rehearsal "钛合金的进口关税税率是多少?"
```

```
我不知道 —— 库里现有的文档回答不了这个问题,已转给人工。

[转人工] 已记录,请联系 陈静 chenjing@example.com(该品类暂无人认领,按兜底规则)
```

### 7)知识缺口清单 —— 交给领导的第二产物

```bash
uv run pqa gaps
```

```
知识缺口清单(按品类,次数多的在前):

【包材】
  - 包材的谈判底价是多少?  ×1

【未分类】
  - 钛合金的进口关税税率是多少?  ×1
```

问得越多的缺口越该先补。老采购走之前,照着这张单子交接。

### 8)访问记录与体检

```bash
uv run pqa audit     # 谁问了什么,是否触及保密 —— 只存本地
uv run pqa doctor    # 再看一次哪些文件没读进来
uv run pqa whoami --as 2001
```

## 接真模型

把 `--driver rehearsal` 去掉就是真实调用(默认 `--driver anthropic`):

```bash
uv sync --extra llm
export ANTHROPIC_API_KEY=sk-ant-...
uv run pqa ingest          # 摄取时给每份文档生成一句话摘要
uv run pqa ask --as 1001 "金属品类的付款账期是多久?"
```

用的是 `claude-opus-5`。**这条路径写了但从没跑过** —— 本项目的测试必须全部离线,
所以真实调用的正确性不由测试保证,而由它极小的体积保证:它只做一件事,
把字符串换成字符串(`src/procurement_qa/llm.py`,约 40 行)。

## 怎么摆文档

```
demo/knowledge/
├── 金属/                     ← 一级目录名 = 品类
│   ├── 金属品类策略2024.docx
│   └── 金属合格供应商名录.xlsx
├── 包材/
├── 流程/
└── 保密/                     ← 保密文件夹:放进来的整份保密
    ├── 金属/                 ← 保密文件夹下再分品类
    │   └── 2024金属供应商报价单.xlsx
    └── 包材/
```

**定密只有一条判据:文档在不在保密文件夹里。** 不在 = 公开。没有第二判据,
没有段落级例外,没有元数据卡片 —— 这是业主明确拍板的(理由和代价见
`docs/adr/0005-folder-is-the-only-classification-mechanism.md`)。

支持的格式:`.docx` `.pdf` `.xlsx` `.xlsm` `.md` `.txt`。其它一律进摄取报告的"未读入"。
扫描件(没有文字层的 PDF)本版**不做文字识别**,但会被单独列出来。

人员名单 `demo/roster.csv`(CSV 或 XLSX 都行,采购负责人自己维护):

| 工号 | 姓名 | 角色 | 负责品类 | 联系方式 |
| --- | --- | --- | --- | --- |
| 1001 | 李强 | 采购员 | | liqiang@example.com |
| 2001 | 王敏 | 品类经理 | 金属;电子件 | wangmin@example.com |

配置在 `pqa.toml`。

## 代码怎么组织

| 模块 | 职责 |
| --- | --- |
| `ingest.py` | 知识库根目录 → 知识目录 + 摄取报告(格式分派、扫描件识别、品类推断、定密、日期抽取) |
| `people.py` | 人员名单(CSV/XLSX 同一个接口),按工号查提问人,按品类查品类经理 |
| `access.py` | **系统唯一的安全边界**:给知识目录和提问人,算出可见 / 被挡下两个集合 |
| `answering.py` | `answer_question(...)` —— 两段式选材、结构化输出解析、出处逐字核验、弃答、转人工 |
| `notices.py` | 在进程内、**不经过模型**地判断问题是否碰到了被挡下的保密文档 |
| `llm.py` | 驱动 seam:`AnthropicDriver`(真,不跑)/ `ScriptedDriver`(测试用) |
| `rehearsal.py` | 离线排练驱动,让演示不依赖网络 |
| `records.py` | 知识缺口 + 访问记录(本地 JSONL) |
| `cli.py` | 薄壳:解析参数、调核心、渲染 |

`answer_question` **不打印任何东西、不读 argv、不知道命令行存在,也不写文件**。
以后接企业微信换的就是 `cli.py` 这一层。

设计决策见 `docs/adr/`,术语见 `CONTEXT.md`,需求与验收见 `.scratch/commodity-qa-bot/`。

## 已知边界(第一版不做)

- 扫描件文字识别(OCR)—— 只**报出来**是哪几份。
- 企业微信接入 —— 只保证核心模块不被 CLI 污染。
- 段落级保密、每份文档的元数据卡片 —— 业主明确否决(ADR-0005)。
- 向量库 / embedding —— 业主明确否决(ADR-0001)。
- 多轮对话、真实身份认证、并发与服务化。
