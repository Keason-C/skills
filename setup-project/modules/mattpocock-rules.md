# Matt Pocock skills

These are the project's default execution rules for to-spec, to-tickets, grilling, and code-review. Where these rules and a skill's own instructions differ, these rules take precedence.

## to-spec

- Once the spec is published, ask the user whether it will be broken into tickets — the split is the user's call; run to-tickets only on a yes.

## to-tickets

- Every ticket carries an `**Effort Level:**` line below `**Status:**`: choose `medium`, `high`, `xhigh`, or `max` and show it in the proposed ticket list.

## grilling

Use the current question tool within its availability and batch limits. If no suitable tool is available, ask a concise question in chat. Resolve the current batch before opening another; preserve the questions that remain.

## code-review

When `code-review` identifies sources for its Standards axis, read `constitution-doc/CODE_REVIEW_STANDARDS.md` if present and include it among the repository standards sources given to the Standards sub-agent. Follow the skill's Standards review instructions.
