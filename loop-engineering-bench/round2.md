# Round 2 评测报告 — PydanticAI 业务分析 agent（S2）

## 背景与目标（每轮报告共用）

**这是在评测什么。** 你想搞清楚一件事：当你只想"给需求 + 做验收"、把中间的想清楚需求→设计→拆任务→写代码→自测这一整段"loop"交给 AI agent 自主跑时，**哪种工作流（skill 组合）最靠谱**。所以我们让三套工作流在**同一道真实开发题**上正面对撞：

- **A = matt 的 skills**：`grilling`（把你盘问透）→ `to-spec`（写规格+ADR）→ `to-tickets`（拆成可执行工单）→ `implement`/`tdd`（按工单实现）。
- **B = 裸 brainstorm 基线**：不挂任何 skill，让 Opus 用它自己认为最好的方式对话、出规划、拆任务。这是对照组，用来量"skill 到底加了多少价值"。
- **C = superpowers 的 skills**：`brainstorming`（对话式想全设计）→ `writing-plans`（写分阶段 TDD 计划）→ `executing-plans`（按计划执行）。

**为什么这么设计。** 核心命题是"agentic coding 不是 vibe coding"——好的工作流应该在动手前**帮你把生产级的坑想全**（而不是热情满满地写出一个上线就炸的 demo），并且能**无人值守地从需求跑到可验收的成品**。所以除了常规的正确性/健壮性/测试/可维护/运维，我们专门加了一个"**思维补全**"维度，看它有没有帮非专家把该想的都想到。

**公平设置（每轮一致）。**
1. 三家拿**一字不差的同一段种子需求**起步、在**各自隔离的 git 仓库**里干活。
2. **规划用 Opus、写码用 Sonnet**，三家同配置。
3. 我（裁判）**全程扮演那个"只懂业务/只定目标、不懂实现"的用户**，agent 的所有提问**只从一份预先写死的需求档案作答**——同一个问题，三家得到**一字不差的同一个答案**；没问到的我不主动说。这样规划质量的差异完全来自工作流本身，而不是我给谁多喂了料。
4. 每家**规划软上限 90 分钟、实现硬上限 4 小时**，超时按现状记。
5. **我不写任何候选代码或规划**，只做裁判：**亲手跑它们的测试、亲手构造对抗输入、亲手复现性能声明**——绝不轻信自我报告。
6. 评分用 7 维加权：正确性与验收 23 / 健壮性 18 / 测试 13 / 可维护性 13 / 运维就绪 9 / Loop 适配 14 / 思维补全 10。

**每轮换一道不同场景的题**，看不同工作流在不同任务形态下的强弱，最后给总评 + 工作流选型建议。

## 结论先行
**排名：A（matt，9.11） > C（superpowers，8.13） > B（裸 brainstorm，8.08）**

与 Round 1（C>A>B）相比**发生反转**：这一轮 A 夺冠。原因一句话——本题范围更聚焦（只两类文件、一条分析管线），A 那套"慢但彻底"的 grilling→ADR→implement 打法**在 4 小时内把 13 张票全做完了**，测试最厚（裁判手跑 208 个）、运维文档最全、还自己抓修了依赖声明；而上一轮靠"运维交付最全"夺冠的 C，这轮运维反而最轻（无 Docker/无 runbook）、测试最少（40 个）、网页层还留了没接完的口子。

三家的核心都对：**都把"算数交给确定性代码、LLM 只解读、再加一道数字核验器"这套反幻觉架构落地了，而且都真·强制、能离线测、不是玩具。** 裁判亲手构造编造数字+注入输入逐一打过，各家防线各有一个可复现的边缘漏洞，且互补（见 §3）。

## 2. 规划阶段：思维补全的深度与时机（证据）
三家最终都收敛到同一反幻觉架构，差别在**谁在哪个阶段想到、讲得多透**：
- **A（matt grilling）**：2 轮 13 问，每问带推荐+理由+代价。主动挖出 5+ 生产坑并教给非技术用户：编造数字、扫描件要OCR、成本护栏、"阈值必须明写死不让LLM自由发挥"（round2/A/docs/adr/0005）、"认表模板替代猜列"（round2/A/docs/adr/0004）。**产出 13 个 ADR**，把每条决策的"为什么/代价/取舍"留给未来维护的两个兼职 Python 同事。思维补全最强。
- **C（superpowers brainstorming）**：8 问，**开场第一句就点破核心**——"算术交给代码而非模型口算、每个数字溯源到源单元格"（任务通知原文）。设计文档含**数据流向图**（round2/C/docs/superpowers/specs/2026-08-05-ai-business-analyst-design.md:258，标出仅两个 egress 点）、真实模型定价成本估算。教学质量第二，仅次于 A 的 ADR 深度。
- **B（裸 brainstorm）**：7 问（1 轮）。提问阶段没挖到深坑，但**在写设计时自己补回了核心架构**（round2/B/SPEC.md §5 确定性计算与LLM分离）。无 ADR、无独立决策记录，"为什么这么定"留痕最少。

规划提问总计：A 13 / C 8 / B 7。实现阶段三家均零人工澄清（无人值守达成）。

## 3. 反幻觉防线对抗验收（裁判亲手打，三家同一套探针）
这是本轮最硬的验证。红线="绝不编数、拿不准标红"。

**C — verify.py（结构化精确匹配）** `round2/C/analyst/verify.py`
- ✅ 精确引真值→clean；✅ 编造value_id→拦；✅ 数字改一位(1420冒充1000)→拦；✅ 引用held-for-human低置信OCR值→拦。
- ❌ **散文洞（坐实）**：把"暴跌37%"塞进 Finding.claim 文本、不进 figures 列表→`is_clean=True` 放行。核验器只扫结构化 figures，散文靠系统提示"NEVER write bare number in claim/recommendation"软兜（round2/C/analyst/analysis.py:86）。
- 特点：无容差、精确（off-by-digit 都逮），但漏散文。

**A — grounding.py / B — guardrail.py（正则扫散文）** `round2/A/src/ba_agent/llm/grounding.py`、`round2/B/src/ba_agent/agent/guardrail.py`
- ✅ 编造"37%/2000/9999(含注入)"散文数→全拦（**逮住 C 漏的那类**）；✅ 真实数放行。
- ❌ **容差洞**：贴近真值1%内的编造数(1005冒充1000)→放行（两家都有，abs0.05/rel0.01）。
- A 额外：❌ `_ALWAYS_ALLOWED={0,1,100}` 小洞（编造"100%"放行）；真值12.5%因保守符号处理被误拦（偏"标红"=安全方向）。

**定谳**：三家核心防线均真·强制、离线可测、非玩具；各有一个可复现边缘洞且**互补**——C 结构化精确但漏散文；A/B 扫散文但有容差洞。理想=C精确+AB散文扫描合体。提示注入三家都防住（C 靠"模型无权报数字"的架构最优雅）。

## 5. 与 Round 1 的对照（趋势）
- **C 不再是万金油冠军**：Round 1 它靠"运维交付最全"夺冠；Round 2 换到 AI-agent 题、范围更聚焦，它的运维反而最轻。说明 superpowers 的强项是**把复杂系统规划全、防呆到位**，但"周一能上线"的容器化/runbook 这类收尾**依赖计划里有没有排这一步**——这轮它的 16 任务计划没排 Docker/runbook。
- **A 从"慢而未竟"变"慢而全胜"**：Round 1 它 4 小时没跑完队列、运维翻车拿第二；Round 2 题目小，它的彻底打法把优势打满、劣势藏住。**A 的表现对"任务范围"最敏感**——范围一大就慢到做不完，范围聚焦就全面碾压。
- **B 稳定第三**：两轮都"能干、但少了 skill 的想全与留痕"，且两轮都各摔一跤（R1 扩范围、R2 漏依赖），印证"无 skill = 无人值守下没有护栏"。
