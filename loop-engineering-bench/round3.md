# Round 3 — S3 真实开源代码库的行为保持重构/优化（httpie/cli）

## 背景与目标（每轮报告共用）

**这是在评测什么。** 你想搞清楚一件事：当你只想"给需求 + 做验收"、把中间的想清楚需求→设计→拆任务→写代码→自测这一整段"loop"交给 AI agent 自主跑时，**哪种工作流（skill 组合）最靠谱**。所以我们让三套工作流在**同一道真实开发题**上正面对撞：

- **A = matt 的 skills**：`grilling`（把你盘问透）→ `to-spec`（写规格+ADR）→ `to-tickets`（拆成可执行工单）→ `implement`/`tdd`（按工单实现）。
- **B = 裸 brainstorm 基线**：不挂任何 skill，让 Opus 用它自己认为最好的方式对话、出规划、拆任务。这是对照组，用来量"skill 到底加了多少价值"。
- **C = superpowers 的 skills**：`brainstorming`（对话式想全设计）→ `writing-plans`（写分阶段 TDD 计划）→ `executing-plans`（按计划执行）。

**为什么这么设计。** 核心命题是"agentic coding 不是 vibe coding"——好的工作流应该在动手前**帮你把生产级的坑想全**（而不是热情满满地写出一个上线就炸的 demo），并且能**无人值守地从需求跑到可验收的成品**。所以除了常规的正确性/健壮性/测试/可维护/运维，我们专门加了一个"**思维补全**"维度，看它有没有帮非专家把该想的都想到。

**公平设置（每轮一致）。**
1. 三家拿**一字不差的同一段种子需求**起步、在**各自隔离的 git 仓库**里干活。
2. **规划用 Opus、写码用 Sonnet**，三家同配置。
3. 我（裁判）**全程扮演那个"只懂业务/只定目标、不懂实现"的用户**，agent 的所有提问**只从一份预先写死的需求档案作答**——同一个问题，三家得到**一字不差的同一个答案**；没问到的我不主动说。这样规划质量的差异完全来自工作流本身，而不是我给谁多喂了料。
4. 每家**规划软上限 90 分钟、实现硬上限 4 小时**，超时按现状记。
5. **我不写任何候选代码或规划**，只做裁判：**亲手跑它们的测试、亲手构造对抗输入、亲手复现性能声明**——绝不轻信自我报告。
6. 评分用 7 维加权：正确性与验收 23 / 健壮性 18 / 测试 13 / 可维护性 13 / 运维就绪 9 / Loop 适配 14 / 思维补全 10。

**每轮换一道不同场景的题**，看不同工作流在不同任务形态下的强弱，最后给总评 + 工作流选型建议。

## 本轮场景（与前两轮的不同）
前两轮是"从零造一个生产级系统"。本轮换成**接手一个真实、成熟、测试完备的开源代码库，做一次行为保持的优化或重构**——考的是完全不同的能力：**读懂别人的代码、在不改任何用户可见行为的前提下让它更好、并证明自己没改坏。**

- **目标库**：`httpie/cli`（著名命令行 HTTP 客户端），锁定 commit `5b604c3`。~19k 行 Python（源码 9.8k + 测试 8k），域复杂度高（CLI 解析、请求构建、输出着色/格式化、会话/cookie、下载流、插件系统）。
- **绿基线（裁判亲手焊死）**：`995 passed, 0 failed`（排除 24 个预存的网络/环境假象：远程 httpbin、big5 字符集库版本、root 无视 chmod、cookie 跨域）。这条 995 绿线 = 重构"不改行为"的护栏。命令见 `dossiers/S3.md`。
- **任务**：挑一个价值最高、能干净落地的重构或优化做掉；测试套件必须一直全绿；聚焦可 review；改进要能测量；**绝不许删测试/改松断言骗绿**。我扮演 httpie 维护负责人（懂代码，但只定目标/约束/验收，让 agent 自己读代码决定改哪、并证明为什么值得）。

## 结论先行
**排名：C（superpowers，9.06） > A（matt，8.88） > B（裸 brainstorm，8.66）**

三家**没有一个跳进陷阱、没有一个改坏行为**——都守住了 995 绿基线、都没弱化测试骗绿。这本身就说明三套工作流在"重构"这种高风险任务上都够格。差别在**靶子的野心、方法的严谨、和改动的可 review 度**：

- **C 夺冠**：选了可维护性重构（把最难读的 `core.program` 分隔符逻辑抽成命名状态机），用**characterize-first**把行为保持做成了**可证明**的——先写 12 个 byte-exact golden 钉死当前输出、再抽取、golden 期望字节全程不变 = 零行为 diff 的铁证。方法最严谨、改动最聚焦、可维护性提升最直接。
- **A 紧随**：选了性能优化（懒加载，把 pygments/ssl/sessions 移出 `--version` 路径），交付了**最大最可测的赢面**（启动 1.87x，裁判复现 ~1.5x），分析最深（还推翻了自己的错判）。但改动面最大（14 文件、~300 行），review 负担和行为敏感度最高，且为提速引入了额外机制（略增复杂度）。
- **B 第三但差距缩小**：一个精准的小手术（SSL import 时白加载 CA 证书，8 行修复），干净、稳、可测。基线扎实，但赢面窄、思维补全最浅——裸 brainstorm 没有 skill 那套"逼你把方法论做严谨"的框架。

**三家都识破了那个诱人的陷阱**：`EncodedStream` 用 `iter_lines(CHUNK_SIZE=1)` 一次读一个字节，看着是免费提速点——**A 靠推理识破**（判断它是 `--stream`/SSE 低延迟的有意设计），**C 靠实证识破**（跑出来证明 chunk_size=1 时跨读取的 `\r\n` 会多吐一个空行、调大就是行为改变）。B 的靶子在 SSL 不涉及此路径。这就是好工作流的价值——**在动手前把"看着能优化其实会改行为"的地雷排掉。**

### 关键证据（带路径行号）
- **A 行为保持**：`--version`/`--help` 输出对基线 `diff -q` 字节一致（裁判实测）；`httpie/plugins/manager.py` 的 `register_lazy` 按 `declared_type` 分型 materialize，只需 auth 插件时不强拉 pygments，注释守注册顺序不变量（round3/A ADR-001）；golden `tests/fixtures/lazy_imports/help.txt`(406 行)捕获完整 --help。诚实披露 2 个残留（requests 因 `tests/test_auth.py` mock `argparser.get_netrc_auth` 模块属性而保持 eager；charset_normalizer 经 Environment 默认参数拉入）+ 5 处计划偏离，均记 MEASUREMENTS.md。
- **B 行为保持**：`httpie/ssl_.py` 加 keyword-only `load_certs=True`，`get_default_ciphers_names` 传 `load_certs=False`；真请求路径（`HTTPieHTTPSAdapter.__init__`）默认不变；`DEFAULT_SSL_CIPHERS_STRING` 保持模块级字符串，`tests/test_ssl.py` import 契约未动。cipher 列表 17 项前后字节一致（裁判实测）。
- **C 行为保持**：`httpie/core.py::program()` 恰好只把 `force_separator`/`prev_with_body` 两循环变量换成 `MessageSeparator` 实例，`separate()` 字节发射留原地，downloader/exit-status/check-status/redirect 全没碰；契约形式化为 `S ⇔ prev_with_body ∧ oo.any() ∧ (force ∨ ¬tty)` + 真值表（round3/C 设计文档 §3）；12 golden 覆盖 TTY/piped × {多消息、streamed-upload、--all redirects…}。

评分要点（白话）：
- **A**：赢在"正确性/验收"（最大最可测的赢面：启动 1.87x、行为字节一致，裁判全复现）和"思维补全"（分析最深，还**推翻了自己"延迟 colors 省 45%"的错判**、精确溯源到 ExplicitNullAuth+plugins/builtin，加"达标即停"检查点）。输在"可维护性/健壮性"——14 文件的大改动引入了懒加载机制（更多间接层），review 负担和行为敏感面（插件注册/help/choices）都最高。**赢面最大，但也最不"小而可 review"。**
- **B**：全维均衡、最稳最小（8 行、行为改不坏），但赢面窄、"思维补全"最浅。裸 brainstorm 到这水位说明底子好，但少了 skill 那套"把方法论做严谨、留决策痕迹"的框架。
- **C**：赢在"健壮性/测试/可维护性"——characterize-first 把行为保持做成**可证明**、改动最聚焦、直接改善了最常读函数的可读性。最贴合维护者"可维护性优先、小而可 review、宁可小而稳不要逞英雄"的诉求。**方法最严谨。**

Loop 适配三家同分（8.5）：均零人工澄清无人值守到底；A 自主导航了最复杂的分阶段计划（用数据自己决定进不进 stage C），C 内建 spec-review 闸门+live 自验证+未触发回退，B 触点最少交付最利落——各有千秋。
