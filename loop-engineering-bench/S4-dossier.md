# S4 需求档案 — 接手"烂摊子"开源库：补测试兜底 + 安全清理 + 可控改进（裁判专用）

## 目标代码库（锁定）
- **soimort/you-get**（广泛使用的命令行视频/媒体下载器），commit 锁 `049548f3f3f35e67ba8d3181c71fdc71d11cf260`（`049548f`）。
- 规模：~14.5k 行 Python。**烂摊子症状确凿**：
  - `src/you_get/common.py` 是 **1886 行的上帝模块**（50 个函数、**13 个裸 `except:`** 吞一切异常、混着网络/文件/解析/CLI 各种关注点）。
  - **只有 4 个测试文件**，且现有"测试"（tests/test.py 等）是**打真实网络**的集成测试（跑去抓 X.com/miaopai 等在线视频信息）——离线必挂、依赖第三方站点、无任何可靠的离线安全网。
  - CI（.github/workflows/python-package.yml）很弱：flake8 只查语法错（E9/F7/F82）+ 跑那批网络 unittest。
  - 纯逻辑函数（`match1`/`matchall`/`parse_host`/`unicodize`/`url_to_module`/`escape_file_path` 等）**零离线单测覆盖**。
  - 安全面：`escape_file_path`(common.py:319) 只把 `/ \ * ?` 换成 `-`，不处理 `..`/控制字符/null/Windows 保留名/`: | < > "` 等——从不可信视频标题生成文件名 = 路径穿越/非法文件名风险。
- 三家各拿一份该 commit 的隔离副本 /workspace/bench/round4/{A,B,C}（已建 venv 装 `-e .` + pytest），分支 round4-hardening。

## 种子输入（三家一字不差的起始指令）
「我接手了 you-get 这个下载器，想把它维护起来。现在最大的问题是我**根本不敢改**——测试基本没有，仅有的几个还得联网跑、动不动就挂，`common.py` 快两千行、到处是 `except:` 吞异常，我改一行都不知道会不会弄坏别的。你先帮我把这摊子理出个**能让我以后敢动手的底子**：该补的测试补上、明显的坑（尤其安全相关的）清一清、但**别把这个几百万人在用的工具改出回归**。挑你觉得最值、最能落地的做，告诉我你做了什么、为什么、怎么验证的。」

## 用户画像（我扮演的角色）
- **刚接手 you-get 的维护者**。懂 Python、能聊技术，但对这份陌生代码的历史/边角行为不熟——所以**特别怕改出回归**。只定目标/约束/验收，让你自己读代码判断改哪。
- 最想要的：**一个能让我以后敢动手的安全网**（真正的离线测试）+ 把**明显的坑（尤其安全）**清掉。
- 最怕的：**把这个百万人在用的工具改出行为回归**（下载不了、文件名变了、参数语义变了）。

## 必须有（Must-have / 硬约束）
1. **补真正的离线测试**：给当前零覆盖的核心纯逻辑（URL/参数解析、文件名处理、模块分发等）补上**不依赖网络、确定性、可复现**的单元/characterization 测试，形成一个我以后能靠的安全网。
2. **不破坏现有行为**：任何用户可见行为都不能回归——CLI 参数语义、下载产物文件名规则（除非是明确的安全修复且你说清）、输出。现有那批网络集成测试不算安全网、也不要求它们离线通过，但**不许删/改松它们来充数**。
3. **安全清理要真实**：若动安全相关的点（如文件名/路径清洗），修复要**有测试证明**修好了、且**不误伤正常文件名**；讲清风险和修法。
4. **改进要聚焦、可 review**：一个连贯、有边界的改进（补测试 + 一两个真实修复），不是全库大重写。上帝模块可以点到为止地理，但别为拆而拆冒行为风险。
5. **不弱化/不删现有测试**充数骗绿。
6. **不加重依赖**：尽量不加新运行时依赖（测试依赖如 pytest 可以）。

## 加分（Nice-to-have）
- 补测试前先 characterize 现有行为（把当前输出钉住），证明你的清理没改行为。
- 修复真实 bug（不止安全）：裸 `except:` 吞掉 KeyboardInterrupt/SystemExit、静默吞错等。
- 给一个能在 CI 里离线跑的测试入口（哪怕只是让新测试 `pytest`/`unittest` 一条命令跑绿），为"以后加真 CI"铺路。
- 覆盖率或"新增测试数 + 覆盖了哪些关键函数"的说明。

## 明确不做（Out of scope，被问到才说）
- 不做新增下载站点/新功能。
- 不做全库大重写 / 拆 common.py 成多模块的大工程（行为风险太高，本轮不值）。
- 不做让那批网络集成测试离线通过（它们本就依赖外部站点，不是本轮目标）。
- 不做升级大依赖/换构建系统。
- 不做纯 flake8 格式化冒充改进。

## 预置答案（被问到才答，没问不说）
- 测试优先级 vs 安全清理：「先要安全网——测试是让我敢动手的前提。安全清理紧随其后，最好是'补了测试顺手把测试暴露出来的安全坑修了'。用哪根杠杆、先后你定。」
- 补哪些测试：「你读代码判断哪些是'核心、纯逻辑、现在零覆盖、坏了影响大'的——URL/参数解析、文件名生成那类最该先兜住。别去给联网的下载器逻辑写网络测试。」
- 现有网络测试怎么办：「别管它们离线过不过，那不是你的锅；但**不许删它们或改松来充数**。你补的是新的、离线的、确定性的测试。」
- 安全到什么程度：「常识性加固就好，别搞成安全审计大工程。文件名/路径清洗这种'不可信输入进来'的点，是我最担心的——如果有真实风险，修，并用测试证明修好了、且没误伤正常文件名。」
- 行为回归红线：「用户能看到的都不能变——CLI 参数、下载出来的文件名规则、正常输出。唯一例外是明确的安全修复（比如挡住恶意文件名），那种你要单独说清'这是有意的行为收紧'。」
- 上帝模块 common.py 要不要拆：「别为拆而拆。近两千行是难看，但拆模块的行为风险这轮不值。你要理，就在'补测试保护 + 小步、可证明不改行为'的前提下点到为止。」
- 改多大：「聚焦、可 review。补一批扎实的离线测试 + 一两个真实的安全/健壮性修复，就很好。别贪大。」
- 怎么算 done：「新测试在我手上一条命令离线跑绿；它们真覆盖了那些关键纯函数；任何修复都有测试证明、且我能看懂你改了什么、为什么、怎么验证的；现有行为没回归。」
- 加依赖：「运行时依赖尽量别加。测试用 pytest 无所谓。」
- 时间：「聚焦的一件活，不是几个月工程。落地点真东西。」
- CI：「你要是能顺手给新测试留一个'离线一条命令跑'的入口、方便我以后接真 CI，加分，但不强求。」

## 验收标准（打分依据，硬性；裁判亲手复验）
A1 **新增测试离线跑绿**：裁判在干净副本上一条命令跑新测试，全绿、不联网、可复现。
A2 **测试真覆盖关键纯逻辑**：抽查新测试确实覆盖了此前零覆盖的核心函数（URL/参数解析、文件名清洗、模块分发等），断言真实行为而非空跑。
A3 **安全/健壮性修复真实**：若声称修了安全坑（如文件名/路径清洗），裁判能构造恶意输入证明**修复前有问题、修复后挡住了**，且正常文件名不受影响。
A4 **零行为回归**：CLI 参数语义、正常文件名规则、正常输出未变（裁判抽查；有意的安全收紧需被明确标注并只影响恶意输入）。
A5 **不删/不改松现有测试**充数（裁判 git diff 审 tests/）。
A6 **characterization 诚实**：若做了行为钉定，捕获的是真实当前行为；清理后这些钉定仍绿=证明没改行为。
A7 **裸 except 等真实健壮性问题**若处理，改得对（如不再吞 KeyboardInterrupt/SystemExit）且有测试或说明。
A8 **无新增运行时依赖**（测试依赖除外）。
A9 **附清晰改动说明**：做了什么/为什么这块最值/怎么验证/风险，reviewer 能据此审。
A10 计划定稿后实现阶段**零人工澄清**（Loop 适配硬指标）。

## 关键陷阱区（"思维补全"评分着眼点）
- **没有安全网就动手 = 头号风险**：好工作流会先给要改的地方补 characterization/测试，再清理——而不是直接改一个零测试覆盖的上帝模块。
- **"补测试"要补对地方**：给联网下载逻辑写脆弱的网络测试没价值；价值在纯逻辑（解析/文件名/分发）的确定性离线测试。分不清的方案在 A2 掉分。
- **安全修复要证明+不误伤**：文件名清洗改严容易误伤正常标题（中文、空格、合法符号）；好方案会同时测"挡住恶意"和"放行正常"。
- **裸 except 的隐蔽危害**：`except:` 吞掉 KeyboardInterrupt/SystemExit，用户 Ctrl-C 都停不下来；识别到并说清才算想到位。
- **范围纪律**：抵住"顺手把 common.py 拆了"的冲动——那是高行为风险的大工程，本轮不值；好方案会明确划边界。
- **行为回归的隐蔽面**：文件名规则、参数解析的边角行为最容易被"清理"时悄悄改掉；characterize-first 才稳。
