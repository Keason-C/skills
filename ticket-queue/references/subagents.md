# 子代理派工

首次派工时读取。模型与 effort 使用 [入口的配置表](../SKILL.md#1-确认计划)；本文件只负责运行机制。

## 配置与上下文

核对当前 `collaboration` 工具及支持的模型、effort，确认所需 skills 可发现。用 `spawn_agent` 的 `model`、`reasoning_effort` 传入已确认的显式覆盖；继承当前主对话时省略对应字段。所需工具或配置不可用时报告阻塞，不自动切换执行方式。

`spawn_agent` 没有工作目录、worktree 或权限参数。每次派工使用唯一 `task_name`，设置 `fork_turns="all"` 继承会话规则，并在 `message` 中先列最少必要的派工上下文，再附对应角色的任务正文。上下文包括角色、仓库与工作目录绝对路径、目标分支、起始 HEAD、运行目录、已有授权，以及本轮所需的交接信息。

明确要求子代理先进入指定目录，核对分支和 HEAD，读取该目录适用的 AGENTS.md 与所需技能，再执行任务；后续命令始终使用该目录。继承的父会话只作为背景，本次角色与票据界定任务范围。新 worktree 使用检出版本，源目录未提交的规则不会自动带入；必要的会话专属规则随上下文传递。技能可发现时保留字面量 `$skill-name` 调用，无需复制正文。

只读诊断在上下文中明确限制为读取与报告，不修改文件、提交或运行会写入现场的命令。这是行为约束，不是工具提供的权限隔离；项目要求强制只读隔离而宿主无法提供时，报告阻塞。

## 工作目录

首次执行一张票前，指挥官核对目标分支与 HEAD，使用 Git 创建独立 worktree。以已确认的本轮目标 HEAD 为基点，选择未占用的绝对路径和唯一临时分支：

```bash
git -C "$ticket_source_dir" worktree add -b "$ticket_branch" "$ticket_worktree" "$ticket_start_head"
```

创建 worktree 属于派工准备，不包含业务修改。保存票号、实际路径、临时分支与起始 HEAD；核对成功后调用 `spawn_agent`，将返回的子代理 ID／任务名登记到同一条记录。逐票完成登记后再派下一票，已派出的子代理可以并发工作。

| 角色 | 指定工作目录 |
|---|---|
| 首次执行一张票 | 为该票创建的独立 worktree |
| 修复、诊断、备用执行 | 该票已登记的 worktree |
| 合并 | 已确认目标分支所在目录 |

每个目录同时只有一个写入者。交接前确认原角色已停止；备用执行与恢复复用现场。指挥官显式管理 worktree，子代理结束不会自动删除目录。

## 消息与生命周期

运行中用 `send_message` 传递补充信息；空闲角色需要继续工作时用 `followup_task`，仅发送消息不会启动新一轮。等待和集中检查按入口执行，等待超时不代表角色失败。

收到 `FINAL_ANSWER`、`task_complete` 或确认角色 idle／errored 后，保存结果并调用 `interrupt_agent` 收尾；收尾不表示该票验收通过。原角色仍可续接时，后续用 `followup_task` 再启动，详见 [恢复会话](recovery.md)。主动停止运行中的角色也用 `interrupt_agent`，交接前核对状态与现场是否仍有写入中的命令。

启动完成条件：票据、worktree、起始 HEAD 与子代理 ID 已唯一对应。派工失败时保留并复用已创建的目录。
