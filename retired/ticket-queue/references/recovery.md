# 恢复会话

仅在续接、运行故障或中断恢复时读取。先查运行日志、`collaboration.list_agents`、worktree 与 Git 状态，确认哪个角色仍拥有写入权。

原子代理仍可访问且配置不变时，用准确的 ID／任务名调用 `followup_task` 续接，提供下一步任务与已登记目录。运行中的角色需要补充信息时用 `send_message`；需要替换时先 `interrupt_agent`，核实原角色及其启动的命令已停止写入后再交接。只停止本次任务的角色和命令。

子代理无法跨宿主会话访问，或需要改变模型／effort 时，重新 `spawn_agent`，复用已登记 worktree，附原任务、已确认配置与授权、必要诊断证据、最后回复和已完成阶段。更新新旧 ID 的映射；不把旧 ID 当成可持久恢复的会话句柄。

同一启动、连接或运行中断故障允许恢复一次；恢复后仍失败就标记对应任务阻塞，不因更换子代理重置次数。这与业务修复计数分开。工具错误、角色状态、现场与最终回复一起用于判断调用是否正常结束。

首次派工失败后先核对已创建的 worktree 和是否已有存活子代理，再恢复派工；不因等待超时重复派工。中断恢复先核实已完成的提交和发布结果，只继续剩余工作，不重复实现、合并或清理。

保留故障结果与进度，按 [子代理派工](subagents.md#消息与生命周期) 收尾已结束的角色，返回入口调度。
