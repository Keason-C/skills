# 整轮合并

仅在本轮可交付票就绪时读取。一个合并子代理独占目标分支写入，接收本轮全部待合并票。

## 唯一任务模板

`x`、`y` 是票号，`<worktree_x>`、`<worktree_y>` 是对应绝对路径；`<merge_reference>` 是本文件的绝对路径。

单票：

```text
合并 issue x 到本分支，交付成功后清理 worktree。
issue x 的worktree：<worktree_x>
合并规则：<merge_reference>
```

多票：

```text
合并 issue x & issue y 到本分支，交付成功后清理 worktree。
issue x 的worktree：<worktree_x>；issue y 的worktree：<worktree_y>
合并规则：<merge_reference>
```

按计划顺序替换全部变量，更多票按同样格式扩展。逐票列出真实票号和路径，不使用范围或省略号，只包含可交付票。向用户展示实际完整提示词作为进度告知。除路径说明外，材料由合并方自己查找。

“本分支”必须是已确认的目标分支。首次派工附上本文件的绝对路径，要求合并方先读取交付规则并按已有授权执行；没有进行中的冲突时先发起集成，有冲突则结合票据、规范和双方改动意图解决并验证。

## 交付与完成条件

合并方核对票据 worktree 已停止写入，读取各自最终 HEAD；所有待交付改动须有本地提交，缺少时在授权范围补齐。Squash 不包含未提交修改。

由同一合并子代理按序逐票 squash、验证并提交，每票一个目标分支提交。保留用户无关修改，按项目约定完成票据收尾。最后一票后的验证须覆盖整轮集成结果。

本轮验证通过后，完成已授权推送和远端票据操作，核对交付结果；只使用既有目标分支，不另开远端分支或 PR。整轮交付成功后，统一清理本轮已合并 worktree 和实际创建的临时分支。

合并引入的冲突或验证失败由合并方处理，本轮合并任务累计最多两轮修复，每轮重新验证。仍失败则保留现场，暂停目标分支后续合并。需要其他角色接手时先交接，保持每个目录一个写入者。

推送失败恢复一次；仍失败则标记待发布并暂停后续交付。中途失败保留未清理现场，记录已合并与剩余票；恢复时核对已有提交，只继续剩余部分，详见 [恢复会话](recovery.md)。

此分支结束于整轮交付并完成清理，或明确报告阻塞／待发布。无授权、验证失败或未交付的现场保留。
